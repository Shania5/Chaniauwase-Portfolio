01 / My contribution

Building the detection foundation.

I selected an indoor dataset, prepared the annotations for object detection, consolidated the source categories into twelve classes, and fine-tuned a pretrained YOLOv8s model. I reviewed the training curves and class-level results to identify where the detector needs improvement.

The original dataset uses twenty classes and includes polygon annotations. My preparation script converts polygons into bounding boxes, merges open and closed doors into a single door category, and combines stair and steps labels. It preserves the training, validation, and test split structure.

Classes: bed, cabinet, chair, door, refrigerator, sofa, table, TV, window, wall, walkway, and stairs.

Dataset: Roboflow indoor, version 2, zxcs-workspace. The supplied export states CC BY 4.0. Original images and annotations belong to the dataset contributors; my work is the preparation and model adaptation. Dataset source ↗

01 / Hardware

A manageable first iteration

I developed on an Apple M2 Mac with 8 GB of unified memory. Earlier attempts involved crashes and long processing times, so I chose a manageable dataset and bounded the training run.

02 / Training

A measured baseline

Training used MPS acceleration, 640-pixel images, batch size 6, AdamW, and a planned 80 epochs. The supplied log covers epochs 4–79; the strongest recorded checkpoint was epoch 54.

03 / Tradeoffs

Scope before scale

The goal of this iteration was a detector I could integrate and test locally. Hardware constraints shaped the approach; the results still need improvement before the assistant can provide dependable feedback.

What the results guide

Improve the examples, then test the experience.

The detector's current performance is uneven. Missed objects and weak table detection are important targets for improvement. Longer training alone is unlikely to resolve those issues.

mAP measures detection performance across classes and matching thresholds; it is not a simple percentage of images classified correctly.

Class performance and technical evaluation +

The F1 curve peaks near confidence 0.167. I would treat this as an experimental starting point, then assess false announcements and missed detections on representative camera footage. A suitable speech threshold must be tested in context.

The training label plot shows uneven class counts. Some counts differ slightly from the supplied source archive, so exact processed dataset totals need reconciliation before a reproducible rerun.

04 / Next development milestone

From detection to spoken descriptions.

Integration planned

  • Load the saved custom weights into a live-camera application.
  • Describe detected objects and their left, centre, or right position in the camera image.
  • Add speech cooldowns and stable-detection checks to reduce repeated announcements.
  • Measure camera performance, detection consistency, and speech latency.

Evaluation planned

  • Review missed detections and incorrect boxes on real indoor scenes.
  • Audit annotations and improve examples for weaker classes.
  • Evaluate the saved model on a held-out test set.
  • Assess useful feedback with users as the prototype develops.

Left/centre/right describes image position. Distance estimation, route planning, and reliable navigation remain future work. The current model is a development prototype.
